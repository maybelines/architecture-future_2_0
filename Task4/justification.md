# Обоснование конфигурации

## Ресурсы

Для задания выбран Yandex Cloud. Стенд состоит из одной VM для небольшой пробной загрузки и аналитических запросов. Camel и ClickHouse устанавливаются на ней вручную. Такой вариант укладывается в доступные квоты и не требует большого количества ресурсов.

| Ресурс | Параметры | Обоснование |
| --- | --- | --- |
| VM app | 2 vCPU, 4 ГБ RAM, Ubuntu 22.04 | Достаточно для демонстрации развёртывания и небольших тестовых таблиц. VM непрерываемая, доля CPU — 100%. |
| Системный диск | 8 ГБ HDD | Минимальный размер для выбранного образа. При установке дополнительных программ потребуется увеличить диск. |
| Диск данных | 1 ГБ HDD | Для тестовых таблиц. Увеличивается отдельно от системного диска, не удаляется автоматически при замене VM. При `terraform destroy` удаляется. |
| Сеть | VPC, подсеть `10.40.1.0/24`, зона `ru-central1-d` | Ресурсы находятся в одной зоне, отдельная сеть упрощает управление доступом. |

Всего используется 9 ГБ HDD. Для полноценного пилота аналитики потребуются диски большего объёма и проверка производительности; SSD здесь не используется ради экономии. Этот стенд демонстрирует IaaS, а не воспроизводит всю архитектуру компании. Отдельные среды доменов, реплики и резервное копирование описаны в заданиях 1–3. Реальные медицинские и финансовые данные на стенд не загружаются.

Terraform создаёт сеть, подсеть, группу безопасности, VM и оба диска. Облако, каталог, доступ аккаунта и SSH-ключ подготавливаются вручную. После `apply` вручную создаётся файловая система, монтируется диск и устанавливаются программы. Границы автоматизации показаны на [диаграмме](./diagram.png).

## NAT и доступ

Параметр `nat = true` выдаёт VM динамический публичный IPv4 для SSH и исходящих соединений, например скачивания пакетов. Отдельный NAT-шлюз для этого стенда не нужен. Назначение параметра приведено в [документации провайдера](https://yandex.cloud/en/docs/terraform/resources/compute_instance).

Группа безопасности разрешает вход только на TCP 22 с адреса `admin_cidr`. ClickHouse настраивается для локальных соединений; Camel обращается к нему на той же VM. Исходящий трафик разрешён для установки программ и обновлений.

## Декларативный подход и IaC

В конфигурации задаётся нужное состояние. Ссылки VM на подсеть, группу безопасности и диск определяют зависимости. Terraform рассчитывает порядок создания, `plan` показывает изменения, `apply` применяет их.

Для повторного стенда используются те же файлы с другими именами и параметрами доступа. У каждого стенда должен быть отдельный state. Версия провайдера закреплена; образ выбирается из семейства Ubuntu 22.04. Если нужна точно та же версия ОС, следует закрепить `image_id`.

CPU, память и размеры дисков меняются через `terraform.tfvars`. Это позволяет увеличивать ресурсы без ручного пересоздания всей инфраструктуры. Изменение CPU и памяти может требовать остановки VM, что допустимо для учебного стенда. Автоматического масштабирования здесь нет.
